# 05 复盘与改进

## 最难的问题

把“模型会规划”与“系统允许做什么”分开：模型可建议替代时间，但不能把建议当用户确认。
保存边界因此独立校验审核、已查询空档和原始请求授权，`pending_confirmation` 不占正式时段。
最终成功状态来自数据库回执，不能直接展示模型口头称成功的文本。

第二个问题是可复现性。Mock 可以跑通路径，却无法证明 ReAct；本项目保留真实 DeepSeek 调用和同场景 Mock，对两类证据明确标记。

## 一次具体修正

测试在 Windows 删除临时数据库时报文件占用。
原因是 Python SQLite 的连接上下文管理器只管理事务提交/回滚，并不负责关闭连接。
测试辅助查询改用显式连接关闭，业务层保持同样做法；实际测试记录见 `examples/test-results.txt`。
随后增加模型提前结束、无可用时段和等价时区输入的回归检查，防止“输出了 JSON 就算成功”。

## 学习与取舍

框架名称没有替代事务和权限边界。选择标准库减少安装成本，把有限时间用于输入、工具结果和保存状态的可验证性。
短公开依据足以解释“观察冲突后改查时段”，无需提交私有思维过程。
幂等不仅是查询已有记录：必须有唯一约束和事务，且拒绝同一键绑定不同输入。
